Same task, two ways

The --with-tools switch

python financial_analysis.py

Claude writes everything

  • Claude writes its own download code and plotting code from scratch
  • Output: coding/ytd_stock_gains.png (YTD % gain)
  • More freedom, but different code every run
python financial_analysis.py --with-tools

Claude uses the helpers

  • The get_stock_prices and plot_stock_prices from stock_tools.py get copied to coding/functions.py
  • Claude is told they exist and just calls them: from functions import …
  • Output: coding/stock_prices_YTD_plot.png (price lines)

The lesson: handing an agent ready-made, tested functions makes it shorter, cheaper and more predictable than letting it write everything.

Where things live

The files

autogen-financial-analysis/
├─ financial_analysis.py builds the agents and starts the chat
├─ stock_tools.py the two helper functions
├─ claude_client.py small fix so ag2 works with Claude
├─ .env your Anthropic key (gitignored)
├─ .venv/ installed packages (gitignored)
└─ coding/ created at runtime: Claude's scripts + charts
Why claude_client.py?

ag2 always sends a temperature setting. Claude Opus 5.5 rejects it. This 10-line file removes it before each request. Everything else is ag2's normal Anthropic support.

Try it

Run it: one command at a time

# 1. Set up once, then add your key to .env
cd autogen-financial-analysis
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

# 2. Run mode 1, then wait for it to finish
python financial_analysis.py

# 3. Then run mode 2
python financial_analysis.py --with-tools

# 4. Look at the charts
open coding/*.png
Gotcha 1

Type the commands without the grey # lines. By default, interactive zsh doesn't treat # as a comment, so the text after it gets passed to the script as arguments.

Gotcha 2

Don't paste step 2 and step 3 together. The second line would be sent into the first chat as your reply.
